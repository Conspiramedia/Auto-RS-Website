## 2. Почта поддержки

Выбран **вариант Б: напрямую на Gmail** — ящики на домене не заводятся.

Контактный адрес площадки — `info.rsauto.rs@gmail.com`. Он проставлен

- `OPERATOR.email` (`lib/legal.ts`) — то, что видит пользователь:
  подвал, `/contact`, разделы «Контакты» политики и условий, JSON-LD

  уходят письма формы обратной связи и заявки салонов. Там же

**исходящий** адрес транзакционных писем через Resend, с него письма
уходят, на него не пишут. Он остаётся на домене и требует
верификации домена в Resend (пункт 1).

## 6a. Админ-комната: назначить администраторов и задеплоить письма

Раздел `/admin` готов (миграции `0078`–`0080` применены 24 августа
2026), но две вещи нельзя сделать правкой кода.

**Назначить администраторов.** Флаг `profiles.is_admin` ставится
только вручную в SQL Editor: RPC для выдачи прав не существует и не
будет — скомпрометированный аккаунт администратора не должен уметь
плодить администраторов.

Порядок на каждого человека:

1. Человек входит на сайт обычным способом — `/login`, SMS на
   **сербский мобильный** (`+381 6X XXX XXX`). Другого входа на сайте
   нет: ни пароля, ни входа по почте. Так создаётся его профиль.
2. Поднять флаг по `id` (не по телефону: промах в `where` при
   `update` затрагивает не ту строку молча):

   ```sql
   select id, email, phone, full_name from public.profiles
    where phone = '+3816XXXXXXXX';

   update public.profiles set is_admin = true where id = 'UUID';
   ```

3. Человек обновляет `/admin` — перезаходить не нужно, флаг читается
   на каждом запросе.

- [ ] Основной администратор назначен: ______ (телефон, дата)
- [ ] Резервный администратор назначен: ______
      Один администратор — точка отказа: потерянный телефон означает,
      что модерация встала до ручного вмешательства в базу.
- [ ] Проверено, что посторонний получает на `/admin` **404**, а не
      форму входа и не 403.

**Задеплоить Edge Function `send-email`.** Миграция `0080` добавила
шаблон `car_archived_by_admin` (письмо продавцу о снятии объявления).
Пока функция не обновлена, такие письма ложатся в `failed` с внятной
ошибкой — они не теряются, но и не уходят.

```bash
supabase functions deploy send-email
```

- [ ] Функция задеплоена после применения `0080`.
- [ ] Проверено после первого снятия объявления:

## 12. Фаза 2 — «Позвонить» (Twilio Voice)

Дизайн принят 23 августа 2026. **Старт C1 — после релиза сайта.**
Кода пока нет: это спроектированная, но не начатая фича.

### Флоу

Кнопка «Позвонить» на карточке (сайт + приложение) → RPC
`request_call(car_id)` → Edge Function `call-bridge`:

1. Twilio звонит **покупателю первым** — иначе продавец слушает гудки
   и платим за звонок в никуда при неответе инициатора;
2. покупатель снял → TwiML `<Dial>` на продавца;
3. `callerId` у обоих плеч — номер Twilio, реальные номера не
   раскрываются ни одной стороне;
4. вебхуки (`/call-twiml`, `/call-status`) деплоятся с
   `--no-verify-jwt` (Twilio JWT не присылает), подлинность —
   **строго по `X-Twilio-Signature`**. Без этой проверки любой
   дёрнет `/call-twiml?call_id=…` и получит реальный номер продавца,
   то есть фича превратится в свою противоположность.

Номер покупателя берётся из `auth.users.phone` (подтверждён OTP).
Параметр `buyer_phone` от клиента **не принимается**: это была бы
возможность заказывать звонки на произвольные номера за наш счёт.

Квоты: 5 звонков/сутки на покупателя, 10 на объявление, 3 на пару
покупатель↔объявление. Журнал `calls` — RLS **deny-all** (в таблице
оба реальных номера); продавцу «кто звонил» отдаёт отдельная RPC
`get_my_calls()` — время, длительность, имя, **без номера**.

Пропущенный у продавца — не ошибка, а лид: уведомление + письмо
через готовый канал Пакета A (`notifications` + `email_queue`).

### Пакеты

| Пакет | Содержание | Переиспользуем |
|---|---|---|
| **C1** Бэкенд | Миграция `calls` + RLS deny-all, `request_call`, `get_my_calls`, квоты | `start_chat` (проверки), `rpc_check_otp_quota` (квоты), deny-all из `email_queue` |
| **C2** Edge | `call-bridge`, `call-twiml`, `call-status` + проверка подписи | Структура `send-email` целиком |

## 13. Фаза 2 — умный поиск (ИИ)

Дизайн принят 23 августа 2026. **Старт AI-1 — после релиза сайта.**
Кода пока нет: это спроектированная, но не начатая фича.

**Блокеры: правовая вычитка (пункт 4) + `AI_MODEL` как флаг.**

Подсказки в строке поиска (`get_suggestion_seeds`, миграция 0073,
`lib/searchSuggestions.ts`) — **отдельная фича без ИИ**, входит в
текущий релиз и здесь не описывается.

### Что делает

Edge Function `parse-query` превращает фразу человека («джип дизель
до 10 000 в Нови-Саде») в набор ОБЫЧНЫХ фильтров каталога. Новый
механизм поиска не создаётся: ИИ лишь заполняет те же поля, которые
человек заполняет руками, поэтому результат виден в URL, шарится
ссылкой и снимается существующими чипсами `FilterChips`.

Две точки вызова: кнопка «Найти фразой» в строке фильтров и
автофолбэк при нуле результатов обычного поиска.

### Контракт

Ответ функции — всегда HTTP 200, в одной из двух форм:

```jsonc
{ "ok": true, "confidence": 0.86,
  "filters": { "brand": null, "model": null, "year_from": null,
               "year_to": null, "fuel": "diesel", "price_max": 10000,
               "city": "Novi Sad", "body_type": "suv" } }

{ "ok": false, "reason": "unavailable" | "quota" | "low_confidence" }
```

Клиент не различает «сломалось» и «не понял»: и там, и там **тихий
фолбэк** на обычный поиск. Значения — только из закрытых списков
(`BRANDS`, `CITIES`, ключи `FUELS` и `BODY_TYPES`), всё остальное
обнуляется на выходе функции. Порог применения — `confidence >= 0.6`.

### Пакеты

| Пакет | Содержание | Переиспользуем |
|---|---|---|
| **AI-1** Квота | Миграция: `smart_search_log`, RLS deny-all, `rpc_check_smart_search_quota` | `rpc_check_otp_quota` (0040) — механика 1:1 |
| **AI-2** Edge | `parse-query`: промпт, JSON-schema, валидация по белым спискам, квота до вызова модели, таймаут 4 с | Структура `send-email` |
| **AI-3** Клиент | `lib/smartSearch.ts`, маппинг в `CatalogFilters`, событие аналитики | `buildQuery`, `parseFilters`, `trackEvent` |
| **AI-4** UI | Кнопка «Найти фразой», состояния, строка «Поняли так», словари sr+ru | `Button`, `Chip`, `Alert`, `FilterChips` |
| **AI-5** Фолбэк | Автовызов при нуле результатов + условия срабатывания | `StateCard`, `EmptyState` |
| **AI-6** Правовое | Раздел об обработке поискового запроса в `privacy`, провайдер как обработчик | `lib/legal.ts` |

### Блокеры

- [ ] **Правовая вычитка (пункт 4).** Фраза пользователя уходит
      стороннему провайдеру модели — в текущей политике это не

### Секреты (задать перед включением)

```

supabase secrets set AI_BASE_URL=…
supabase secrets set SMART_SEARCH_IP_SALT=…

```

Ключ модели живёт **только** в секретах функции: на клиент не уходит
ничего, кроме разобранных фильтров.

### Расходы и квота

Первая фича после «Позвонить» с прямыми переменными расходами, причём
автофолбэк по своей природе срабатывает **без участия человека** —
поэтому квота проверяется ДО обращения к модели, иначе она не
защищает от трат вовсе.

Лимиты: **20 запросов в сутки** на вошедшего, **5** на гостя (ключ —
хэш IP с солью из секрета; сырой IP не пишем — это персональные
данные). Автофолбэк дополнительно ограничен условиями: фраза длиннее
одного слова и один раз на одно значение `q` за сессию.

### Аналитика

Событие `smart_search_used` со свойствами `trigger`
(`button` | `fallback`), `outcome` (`applied` | `low_confidence` |
`unavailable` | `quota`) и `fields` — числом распознанных полей.
**Текст запроса в аналитику не отправляется** ни при каких условиях:
Plausible не собирает персональные данные, и фраза пользователя туда
попадать не должна.

## 14. Фаза 2 — VIN в подаче

Дизайн принят 23 августа 2026. **Старт V1 — после релиза сайта.**
Кода пока нет: это спроектированная, но не начатая фича.

### Что делает

Поле VIN в форме подачи — **только для продажи** (в аренде кузовной
номер не запрашивается и не показывается). Для частного продавца поле
**опционально**, для дилера — **обязательно**: салон обязан знать VIN
машины, которую выставляет, а частник может его не найти или не хотеть
указывать.

### Хранение и публикация

VIN хранится **полностью** (17 символов), а публикуются **последние 6
символов** — «…XK4821». Полный номер видят только владелец объявления и
модератор.

Причина: полный VIN в открытом доступе позволяет собрать историю
конкретной машины и увязать её с владельцем, а также облегчает
перевешивание номера на клон. Последние 6 символов при этом решают
задачу покупателя — сверить, что объявление и машина в реальности одна
и та же.

### Валидация (ISO 3779)

Проверка **на бэкенде**, как и вся остальная валидация полей:

- ровно **17 символов**;
- допустимы `A–Z` и `0–9`, **кроме `I`, `O`, `Q`** — стандарт исключает
  их, чтобы не путать с `1` и `0`;
- ввод нормализуется к верхнему регистру, пробелы и дефисы срезаются.

Контрольная цифра (позиция 9) **не проверяется**: она обязательна в
Северной Америке и необязательна для европейских производителей —
жёсткая проверка отбраковала бы легальные VIN машин с сербского рынка.

### Совместимость RPC

`create_car_v3` и `update_car_v3` получают **опциональный параметр с
дефолтом `NULL`**. Приложение вызывает эти RPC без нового аргумента —
вызовы **не ломаются**, поле просто остаётся пустым до выката V4.
Новые сигнатуры добавляются аддитивно, старые не удаляются.

### Дедупликация

При подаче объявления с VIN, который уже есть у **активного**
объявления, — **флаг модератору**, не жёсткий блок.

Мягко потому, что совпадение бывает законным: перепродажа машины,
повторная подача после снятия, салон и прежний владелец. Жёсткий блок
превратил бы каждый такой случай в обращение в поддержку, а модератор
видит контекст и решает за минуту.

| Пакет | Содержание | Переиспользуем |
|---|---|---|
| **V1** Бэкенд | Миграция: колонка `vin` + индекс, нормализация и валидация в триггере, маскирование в выдаче | Нормализация полей подачи, `get_car_details` |
| **V2** RPC | Опциональный параметр в `create_car_v3` / `update_car_v3`, обязательность для дилера | Существующие сигнатуры `_v3` |

| **V6** Правовое | Раздел о VIN в `privacy` | `lib/legal.ts` |
