# Чек-лист релиза RS Auto

Незакрытые **ручные и конфигурационные** задачи: то, что нельзя сделать
правкой кода — покупка домена, записи DNS, ключи провайдеров,
регистрационные данные юридического лица, вычитка юристом.

Задачи по коду здесь не дублируются: они живут в `README.md` → TODO.

**Правило:** пункт закрывается — отмечается здесь же (`[ ]` → `[x]`) с
датой и фактическим значением, если оно не секрет. Файл обновляется в
том же коммите, что и закрывающее изменение.

Статус на 23 августа 2026: **сайт функционально готов, релиз держат
пункты 1–5.**

## 1. Домен `rsauto.rs`

Порядок важен: пока домена нет, письма уходить не могут (Resend требует
верифицированный домен отправителя), а canonical и OG указывают на
временный адрес Vercel.

- [ ] Купить домен `rsauto.rs`.
- [ ] DNS для Vercel: A/CNAME по инструкции панели → домен привязан к
      проекту, HTTPS выпущен.
- [ ] DNS для Resend: записи **SPF** и **DKIM** из панели Resend →
      дождаться статуса «Verified». Без них письма не отправляются
      вовсе, а не «попадают в спам».
- [ ] `NEXT_PUBLIC_SITE_BASE_URL=https://rsauto.rs` в переменных Vercel
      (Production) → **redeploy** (переменная читается на сборке,
      без пересборки старый адрес останется в canonical и sitemap).
- [ ] Адрес на сервере — тем же значением, иначе `site_url` объявлений
      разойдётся с canonical:
      ```sql
      select public.set_site_base_url('https://rsauto.rs');
      ```
- [ ] `supabase secrets set MAIL_FROM=noreply@rsauto.rs`
      (в секрет кладётся **голый адрес**; отображаемое имя «RS Auto»
      функция подставляет сама — строка вида `RS Auto <…>` в этой
      переменной сломает отправку).
- [ ] `supabase secrets set RESEND_API_KEY=re_…`
- [ ] `supabase functions deploy send-email` + расписание `*/5 * * * *`
      (Dashboard → Edge Functions → Schedules).

Проверка: сменить статус тестового объявления на `active` → строка в
`email_queue` со статусом `sent` в течение 5 минут.

## 3. Реквизиты оператора (APR)

Блокирует релиз: публичная оферта без регистрационных данных
неполноценна, а выдуманный номер APR — нарушение сам по себе.

- [ ] **MB** (матични број) — `lib/legal.ts` → `OPERATOR.registrationNumber`
- [ ] **PIB** (налоговый номер) — `OPERATOR.taxNumber`
- [ ] **Адрес регистрации из выписки APR** — `OPERATOR.address`.
      Именно регистрационный, не фактический адрес работы и не адрес
      для корреспонденции.
- [ ] После заполнения всех трёх `OPERATOR_VERIFIED` становится `true`
      автоматически, и блоки реквизитов появляются на `/contact` и в
      разделах «Контакты» обоих документов. Проверить обе локали.

Телефон поддержки **не заводится** — решение принято, поддержка только
по электронной почте. `OPERATOR.phone` остаётся пустым.

## 8. Deep links (AASA / assetlinks)

Значения известны только владельцу, из репозитория их взять негде.

## 13. Фаза 2 — умный поиск (ИИ)

Дизайн принят 23 августа 2026. **Старт AI-1 — после релиза сайта.**
Кода пока нет: это спроектированная, но не начатая фича.

**Блокеры: правовая вычитка (пункт 4) + `AI_MODEL` как флаг.**

Подсказки в строке поиска (`get_suggestion_seeds`, миграция 0073,
`lib/searchSuggestions.ts`) — **отдельная фича без ИИ**, входит в
текущий релиз и здесь не описывается.

### Что делает

Edge Function `parse-query` превращает фразу человека («джип дизель
до 10 000 в Нови-Саде») в набор ОБЫЧНЫХ фильтров каталога. Новый
механизм поиска не создаётся: ИИ лишь заполняет те же поля, которые
человек заполняет руками, поэтому результат виден в URL, шарится
ссылкой и снимается существующими чипсами `FilterChips`.

Две точки вызова: кнопка «Найти фразой» в строке фильтров и
автофолбэк при нуле результатов обычного поиска.

### Контракт

Ответ функции — всегда HTTP 200, в одной из двух форм:

```jsonc
{ "ok": true, "confidence": 0.86,
  "filters": { "brand": null, "model": null, "year_from": null,
               "year_to": null, "fuel": "diesel", "price_max": 10000,
               "city": "Novi Sad", "body_type": "suv" } }

{ "ok": false, "reason": "unavailable" | "quota" | "low_confidence" }
```

Клиент не различает «сломалось» и «не понял»: и там, и там **тихий
фолбэк** на обычный поиск. Значения — только из закрытых списков
(`BRANDS`, `CITIES`, ключи `FUELS` и `BODY_TYPES`), всё остальное
обнуляется на выходе функции. Порог применения — `confidence >= 0.6`.

### Пакеты

| Пакет | Содержание | Переиспользуем |
|---|---|---|
| **AI-1** Квота | Миграция: `smart_search_log`, RLS deny-all, `rpc_check_smart_search_quota` | `rpc_check_otp_quota` (0040) — механика 1:1 |
| **AI-2** Edge | `parse-query`: промпт, JSON-schema, валидация по белым спискам, квота до вызова модели, таймаут 4 с | Структура `send-email` |
| **AI-3** Клиент | `lib/smartSearch.ts`, маппинг в `CatalogFilters`, событие аналитики | `buildQuery`, `parseFilters`, `trackEvent` |
| **AI-4** UI | Кнопка «Найти фразой», состояния, строка «Поняли так», словари sr+ru | `Button`, `Chip`, `Alert`, `FilterChips` |
| **AI-5** Фолбэк | Автовызов при нуле результатов + условия срабатывания | `StateCard`, `EmptyState` |
| **AI-6** Правовое | Раздел об обработке поискового запроса в `privacy`, провайдер как обработчик | `lib/legal.ts` |

### Блокеры

- [ ] **Правовая вычитка (пункт 4).** Фраза пользователя уходит
      стороннему провайдеру модели — в текущей политике это не
      описано. **AI-6 выполняется строго ДО запуска фичи** и попадает
      в ту же вычитку юристом, что и остальные документы. При правке
      формулировок поднять `POLICY_VERSION` в **трёх** местах
      (`lib/legal.ts`, `lib/consent.ts`, `policy_content.dart`).
- [ ] **`AI_MODEL` как флаг.** Пока переменная не задана, кнопки
      «Найти фразой» нет вовсе и автофолбэк не срабатывает — ровно
      так же, как аналитика выключена без
      `NEXT_PUBLIC_PLAUSIBLE_DOMAIN`. Это позволяет выкатить код
      заранее и включить фичу отдельным действием, после юриста.

### Секреты (задать перед включением)

```
supabase secrets set AI_API_KEY=…
supabase secrets set AI_MODEL=openai/gpt-oss-20b
supabase secrets set AI_BASE_URL=…
supabase secrets set SMART_SEARCH_IP_SALT=…
supabase functions deploy parse-query
```

Ключ модели живёт **только** в секретах функции: на клиент не уходит
ничего, кроме разобранных фильтров.

### Расходы и квота

Первая фича после «Позвонить» с прямыми переменными расходами, причём
автофолбэк по своей природе срабатывает **без участия человека** —
поэтому квота проверяется ДО обращения к модели, иначе она не
защищает от трат вовсе.

Лимиты: **20 запросов в сутки** на вошедшего, **5** на гостя (ключ —
хэш IP с солью из секрета; сырой IP не пишем — это персональные
данные). Автофолбэк дополнительно ограничен условиями: фраза длиннее
одного слова и один раз на одно значение `q` за сессию.

### Аналитика

Событие `smart_search_used` со свойствами `trigger`
(`button` | `fallback`), `outcome` (`applied` | `low_confidence` |
`unavailable` | `quota`) и `fields` — числом распознанных полей.
**Текст запроса в аналитику не отправляется** ни при каких условиях:
Plausible не собирает персональные данные, и фраза пользователя туда
попадать не должна.
