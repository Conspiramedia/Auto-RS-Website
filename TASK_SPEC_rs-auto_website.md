# Задача: создание сайта RS Auto (разовая спека)

Правила поведения — в CLAUDE.md. Этот файл — задача на сборку:
что строим, в каком порядке, критерии приёмки.

## Шаг 0. Аудит (до кода)
Изучи репозиторий приложения: структура, модель данных, реальный API или
mock, дизайн-токены, логотип. Верни 5–7 пунктов и начинай только после
моего подтверждения.

## Бизнес-цели (приоритет)
1. Привлечение продавцов: подача объявления без приложения.
2. SEO-трафик: карточки + категории (марка/модель/город).
3. Воронка в приложение: чат и push — только в приложении; smart banner
   и «Открыть в приложении» на всех страницах.
4. Виральность: sharable-ссылки с OG-превью (фото, цена, модель).

## Политика по бэкенду
- Сайт — второй клиент того же Supabase, без дублей сущностей.
- Если приложение на mock-данных: создай бэкенд как источник правды,
  но приложение НЕ переводи сам — план миграции в README (TODO).

## Модель данных (если бэкенда ещё нет)
User (phone, name), Listing (brand, model, year, price, mileage, fuel,
gearbox, city, description, photos[], status, seller_id), Subscription
(фильтры + контакт), справочник марок/моделей. Если модель уже есть
в приложении — возьми её.

## Страницы MVP (порядок сборки)
1. Карточка /car/{id}: SSR, OG, JSON-LD (Vehicle), галерея,
   «Написать/позвонить — в приложении» (deep link + QR), «Поделиться»,
   похожие объявления.
2. Каталог /cars: фильтры + применённые чипсами с ×, сортировка. Mobile-first.
3. SEO-страницы /cars/{brand}/ и /cars/{brand}/{model}/.
4. Подача /sell: пошаговая форма, валидация, модерация.
5. Главная: оффер продавцу, CTA подачи, свежие объявления, популярные марки.
6. Empty state: «Ничего не нашли» + «Сбросить фильтры» + «Сообщить, когда появится».
7. /app: о приложении, бейджи сторов, QR.
8. /dealers: оффер дилерам «первые 3 месяца бесплатно», форма заявки.

## Воронка в приложение
- Smart banner сверху на мобильных.
- Контакты продавца — через «Продолжить в приложении».
- AASA / assetlinks.json (bundle id — из моих ответов).
- QR на карточке в десктопе.

## Антиспам и модерация
- OTP до публикации; honeypot + rate limit;
- публикация только после модерации; минимальная /admin (basic auth через env).

## Порядок работы
1. Аудит → моё подтверждение.
2. Структура, схема/миграции, сид 20–30 демо-объявлений.
3. Страницы в порядке MVP; после каждого этапа сборка проходит.
4. Секреты — только в .env.example.
5. README: запуск, env, TODO (SMS/S3/deep links/платёжный провайдер).
6. Отчёт после каждого этапа.

## Definition of done
- npm run build без ошибок; SSR отдаёт контент (curl).
- Подача end-to-end: форма → модерация → каталог → карточка.
- Карточка: OG, canonical, JSON-LD, кнопка в приложение, QR.
- Файлы приложения не изменены; коммитов без команды нет.
